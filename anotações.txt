- Git - Um sistema de versionamento para controlar versões (chamadas 
de commits) de projetos/documentos.

- Github - Um serviço online de projetos gerenciados pelo Git.

- Repositório remoto e local: Um projeto controlado pelo git é chamado 
de repositório de versionamento.

1 - Repositório remoto: Tipicamente uma cópia "oficial" do repositório
fica salvo em um servidor.

2 - Repositório local: Cada pesso que trabalha no projeto pode fazer 
uma cópia do repositório para seu computador (repositório local). 
A pessoa então faz suas alterações no projeto (novos commits) e depois
salva as alterações no servidor.

- git pull e git clone: ambos servem para trazer o projeto remoto para seu
computador, mas são utilizados de formas singulares:

1 - git clone: utilizado quando você quer clonar o repositório e iniciar suas
atualizações no projeto.

2 - git pull: utilizando quando você já tem seu repositório local e quer
atualiza-lo com as novas informações que estão no repositório remoto.

- git commit -m "mensagem": O método utilizado no git para salvar seu projeto.

- git push: utilizado para enviar seus commits para o repositório remoto.

- Configurar chave SSH para o Github:

1 - SSH é um protocolo para comunicação de dados com segurança;

2 - O Github aboliu a autenticação somente com usuário e senha;

3 - A ideia básica é cadastrar previamente quais computadores podem
acessar o Github em seu nome. Outros computadores não conseguem acessar;

4 - Para isso você deve:
4.1 - Gerar uma chave SSH no seu computador (rode os comandos pelo Git Bash);
Comando: ssh-keygen -t ed25519 -C "your_email@example.com"
ou: ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
4.2 - Cadastrar essa chave no seu Github.

- git init: Cria um repositório Git na pasta em que está situado.

- git add: adiciona os arquivos do projeto a uma área temporária (stage), você
pode escolher quais arquivos irão ser adicionados ou adicionar um .
para adicionar todos os arquivos do projeto.

- git status: verifica se tem algo a ser salvo.

- git branch -M main: Altera o operador para main

- git push -u origin main: envia o arquivo para o repositório remoto
utilizando o main como origem do commit (Necessário apenas no primeiro push).

- git log: verifica o histórico de versões.

- git log --oneline: verifica o histório de versões de forma resumida.

- Explicação dos status do git status:
1 - Modified: Quer dizer que o arquivo foi modificado;
2 - Untracked: Quer dizer que o arquivo ainda não foi adicionado ao repositório;
3 - Deleted: Quer dizer que o arquivo foi deletado.

- git diff: Comando que mostra a diferença entre arquivos modificados.

- git checkout: Permite modificar temporariamente os arquivos do projeto ao estado
de um dado commit ou branch.

- Código do commit, HEAD:
1 - Cada commit possui um código que pode ser utilizado para referenciar o commit;
2 - O último commit do histórico do branch corrente também pode ser referenciado pela palavra HEAD
3 - É possível referenciar um commit N versões antes de HEAD usando ~N, por exemplo:
3.1 - HEAD~1 (penúltimo commit);
3.2 - HEAD~2 (antepenúltimo commit).

Importante: antes de fazer o checkout para voltar para HEAD, certifique-se de que não haja
mudanças nos arquivos. Se você acidentalmente mudou alguma coisa, desfaça as modificações usando:

1 - git reset: limpa qualquer inclusão feita no git add;
2 - git clean -df: remove arquivos e diretórios não rastreados (untracked) do seu repositório;
3 - git checkout -- .: Limpa todas as alterações do commit que você está.

- git checkout nomeDoBranch: Vai pro último commit do branch selecionado.

- Arquivo .gitignore: É um arquivo que indica o que não deve ser salvo pelo Git.
Geralmente o arquivo .gitignore fica salvo na pasta principal do repositório. Mas também
é possível salvar outros arquivos .gitignore em subpastas do repositório, para indicar o que
deve ser ignorado por cada subpasta.

- Casos comuns e arquivos que não devem ser salvos pelo Git:
1 - Arquivos compilados: Lungiagens compiladas (C, C++, Java, C#, etc.) geram arquivos de
código compilado para executar o programa localmente.
2 - Arquivos de bibliotecas externas usadas no projeto: Projetos reais utilizam bibliotecas
externas (programas prontos disponíveis na internet). Por exemplo, projetos JavaScript com NPM
tipicamente salvam uma subpasta "nome_modules" na pasta do seu projeto.
3 - Arquivos de configuração da sua IDE: IDE's podem salvar uma subpasta com arquivos de 
configuração na pasta do projeto (exemplo: .vscode).
4 - Arquivos de configuração do seu sistema: Por exemplo, sistemas Mac podem gravar uma subpasta
.ds_store na pasta do projeto. 

- Ações que podem abrir o editor VIM:
1 - Fazer um commit sem mensagem;
2 - Fazer um merge de três vias.

- Comandos:
1 - i: Habilitar o modo de edição;
2 - <ESC> | :wq | <ENTER>: Sair do VIM, salvando as alterações (w = write | q = quit);
3 - <ESC> | :q! | <ENTER>: Sair do VIM, descartando as alterações.

- git reset --soft HEAD~1: Desfaz um comit mantendo as modificações nos arquivos.

- git reset --hard <código do commit>: Volta o projeto ao estado de um dado commit 
(deleta commits e alterações posteriores a esse commit). -> Ação destrutiva!

- git reset --hard HEAD~1: Volta o projeto ao estado do penúltimo commit. -> Ação destrutiva!

- git pull <nome do remote> <nome do branch>: atualiza o repositório local em relação ao remoto

- Push rejeitado: Não é permitido enviar um push se seu repositório local está atrasado em relação
ao histórico do repositório remoto, para resolver isso, é necessário utilizar um git pull para atualizar
seu repositório local, esse pull é feito em ordem cronológica, então se os commits locais foram feitos
após o remoto que está desincronizado, ele será incluído cronológicamente antes dos commits locais, e
no fim será adicionado um commit de merge.

- Conflito no pull: Ocorre quando há 2 históricos divergentes que sofreram alterações em arquivos iguais,
para resolver, ao dar o pull, o sistema informará que ocorreu um conflito no(s) arquivo(s) e o bash te
coloca em uma branch "MERGING" para resolver esse conflito, se for utilizado um git status, ele te
mostrará qual arquivo entrou em conflito, e ao verificar o arquivo, você notará que há uma anotação
feita pelo git mostrando oque estava no repositório remoto e a alteração que você fez no repositório
local, para que seja feita a averiguação e correção do código, para finalmente fazer um novo commit e
utilizar o git push.

- git push -f(force) <nome do remote> <nome do branch>: Sobrescreve um histórico no Github. -> Ação 
destrutiva!

- git remote set-url origin SSH path: aponta o projeto para outro repositório remoto.

- git remote -v: mostra para onde está sendo apontado o repositório remoto.
